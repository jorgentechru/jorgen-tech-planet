# Архитектура JORGEN TECH PLANET

## Поток интерфейса
`index.html` создаёт общий header, остров, приложение, footer и dialog. `app.js` выбирает мир или hash-маршрут, создаёт SVG-сцену и обрабатывает переходы. `modules.js` строит раздел, подключает действия и читает/меняет состояние через `data.js`. `author.js` является единственным источником имени/контактных ссылок.

## Файлы и границы ответственности

| Файл | Ответственность |
|---|---|
| `dist/index.html` | Семантическая оболочка, meta/OG, favicon, доступные точки входа |
| `dist/style.css` | Общая типографика, оболочка, состояние острова, адаптивные компоненты |
| `dist/app.js` | Навигация по hash, island state, About, карточки, введение, движение авто |
| `dist/camera.js` | Камера SVG, панорамирование, колесо, pinch, переходы, восстановление |
| `dist/world.js` | Координаты зданий, изометрическая проекция, геометрия и слои |
| `dist/modules.js` | Automotive, Commerce, Studio, Control и обработчики компонентов |
| `dist/data.js` | Фикстуры, расчёты, sessionStorage, создание/сброс демозаписей и заказов |
| `dist/art.js` | SVG-иллюстрации товаров и автомобиля |
| `dist/author.js` | Имя, роль, email, Telegram, GitHub, портфолио |

## Модель состояния
Данные одного браузерного tab хранятся в ключе `wl-demo-v1`: `vehicle`, `services`, `bookings`, `cart`, `orders`, `favorites`. Камера отдельно сохраняется как `world-camera`; отметка знакомства — `world-intro`. Данные могут пережить восстановление вкладки; кнопка Control Center очищает бизнес-демо, но оставляет положение камеры.

## Расчёты
Сумма Automotive — сумма выбранных услуг; класс SUV применяет коэффициент 1.2. Длительность — сумма нормативов услуг. Нельзя создать пустую запись или занятую дату/время (кроме отменённой). Commerce subtotal — цена каждого товара умноженная на количество; демо checkout создаёт заказ и обнуляет корзину.

## Дальнейшее развитие
Не импортировать Sites SDK или секреты в приложение. Для Python API определить DTO и версионировать endpoints; заменить локальные операции data adapter вызовами API постепенно. На сервере пересчитывать сумму из каталога, проверять временной слот и принадлежность каждого объекта сессии. Добавить хранилище и TTL только после отдельного решения.
